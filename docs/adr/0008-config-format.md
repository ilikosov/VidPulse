# ADR 0008: Типизированный YAML-конфиг (@vidpulse/config) вместо .env

- **Status:** Accepted
- **Date:** 2026-07-18
- **Owners:** Backend team
- **Tags:** config, tooling, dx
- **Related:** `packages/config`, `apps/server/src/config.ts`, `packages/db/src/knexfile.ts`

---

## 1) Context

Конфигурация была плоским `.env` (dotenv/dotenv-cli): без типизации значений, без валидации файла, с
двумя источниками (`apps/server/src/config.ts` и независимо `packages/db/src/knexfile.ts`), с двумя
файлами окружений (`.env` / `.env.test`) и без механизма миграции формата. Требовалось: **типизация**,
**валидация файла**, **окружения test/work в одном файле**, **миграция файла**.

## 2) Decision

Новый компилируемый пакет **`@vidpulse/config`** — единый источник конфигурации, который читают и
сервер, и knexfile.

- **Формат:** один YAML-файл `vidpulse.config.yaml` с `version`, секцией `default` и `environments.<NODE_ENV>`
  (deep-merge `default` + секция окружения; `NODE_ENV` выбирает секцию, дефолт `development`).
- **Типизация + валидация:** схема на **zod** (`schema.ts`) — единственный источник и TS-типа
  (`Config = z.infer<…>`), и рантайм-валидации файла (при неверном типе/форме — понятная ошибка,
  fail-fast на старте). `database.path` резолвится в абсолютный относительно файла конфига.
- **Только файл:** `.env`/dotenv-cli убраны; значения (включая секреты и тест-оверрайды) — в файле.
  `config` — живой мутируемый объект, поэтому тесты переопределяют значения напрямую
  (`config.files.renameTemplate = …`) вместо `process.env`. `NODE_ENV` остаётся селектором режима.
- **Версионирование и миграции:** поле `version` + упорядоченные шаги (`migrations.ts`, по образцу
  knex). При **добавлении параметров** поднимается `CURRENT_CONFIG_VERSION`. **При старте**
  (`ensureConfigFile`): файла нет → создаётся с дефолтами; версия ниже → авто-миграция до актуальной
  (`.bak`-бэкап, недостающие новые ключи добираются из дефолтов схемы, значения пользователя
  сохраняются); версия выше → ошибка. CLI `npm run config:migrate` делает это явным шагом.
- Файл **в `.gitignore`** (не коммитится): дефолты живут в коде (схема + шаблон), файл авто-создаётся
  при первом старте/тесте. Секреты (youtube.apiKey и т.п.) держатся локально в этом файле.

## 3) Consequences

- **+** Значения типизированы и валидируются; ошибки конфига видны сразу и понятно.
- **+** Один файл на все окружения; единый источник для сервера и БД-слоя (нет рассинхронизации
  `DATABASE_PATH`).
- **+** Формат версионируется и мигрируется.
- **−** Новая зависимость `zod`; секреты в трекаемом файле требуют дисциплины (skip-worktree/приватный
  чекаут).
- **−** ~30 тестов переведены с `process.env`-мутаций на мутацию объекта `config` (разовая правка).
